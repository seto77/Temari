## 1. ⚠ 取り下げ済み — 前回の「最優先課題」

`next_phase_2026-08-12.md` §2 は「s を 16 まで伸ばしたのに出荷形式が運べていない」
（M4/M5 の 24 % が量子化で 0 に潰れる）を最優先に挙げていた。**これは数え方の誤り。**

- 節点の**数**では 24 %（250,357 個。`gen_golden.py` の報告と厳密一致）
- **重み**で測ると、潰れる分の Σ|F| は**1 行あたり ≤ 1.03e-05**（F(0)=1 比、
  符号が全部揃う最悪値）。μ_hg の対角が F(0)=1 なので、**数と害は 4 桁違う**
- s>8 の求積誤差 3.2e-07 は量子化の半歩 5e-07 と同オーダー ⇒
  **形式を精密にしても運ぶのはノイズ**

⇒ **A4（現形式維持）で決着。A1–A3 は実装しない。**
⇒ **「M4/M5 の高 s が μ に効くか」を ALCHEMI 側で測る必要も無い**（効いても上界 1e-5）。

潰れが M4/M5 に集中する理由も実測した — |F| の減衰指数が**始状態 l で層別**される
（s≥6 窓の中央値で l=0: −3.2 / l=1: −4.4 / l=2: −7.3）。
⚠ **s=16 でもまだ漸近域に入っていない**ので、特定の指数を主張しないこと。

### P1. 閾値直上の求積監査 ★最優先

F(8) = +0.467、**F(14) = −0.319**、ε = 0.639。**この領域の求積誤差は未測定。**

3. HIGH と各 bump の `max|ΔF|` を**保証域内だけ**で測る
4. **高過電圧 3 ケースの既存結果を変えない**
5. 結果を本書へ反映

対象: `src/gen_production.jl` の `audit()`。

### P2. `check_tables` の C2 検査窓を再設計

`tools/check_tables.jl` の K 殻単調性検査は `i_s4 = argmin(abs.(s .- 4.0))` で
**81 点時代の名残**。s が 16 まで伸びた今、**収録範囲の 1/4 しか見ていない**。
⚠ **単純に広げてはいけない** — K でも高 s では物理的に正常な符号反転が起きる
（v5 の QC で 338 本以上）。

1. 全 K チャネルで最初の極値・最初のゼロ交差・E0 依存を**実測**
2. 「正値かつ単調減少であるべき領域」をデータから定義
3. 物理的符号反転を誤検知しない C2 へ
4. **意図的な異常データで C2 が確実に落ちる回帰試験**を足す（[[prove-the-check-can-fail]]）
5. C2 の説明文と実装の窓を一致させる

### P3. ★ GOS 比較の ridge 帯のずれ — 今回新しく見えた課題

比較を単位換算込みでやり直した結果、**帯で切ると構造が出た**
（比 = 我々/先方、ε ≥ 10 eV、ρ = q/q_ridge）:

| 帯 | Fe K | Fe L1 | Au L3 | Au M5 |
|---|---:|---:|---:|---:|
| optical (ρ<0.3) | 0.939 | 0.990 | **0.966** | 1.007 |
| ridge (0.8–1.5) | **1.293** | **1.204** | **1.349** | **1.501** |

**双極子域では 4 チャネルとも 0.94–1.01 に締まる**のに、**ridge に乗ると
1.20–1.50 へ揃って開く**。単一の数値（Fe K = 0.9425 等）はこの構造を潰していた。

⚠ **原因は未特定。**候補は (a) 処方差（先方 = FAC の LDA、我々 = Dirac SCF + Xα）、
(b) 先方の ΔE 上限 4000 eV 近傍の格子端、(c) 我々の求積。**主張しないこと。**

切り分けの筋:
1. 先方の ΔE 上端から離れた帯だけで測り直す（(b) の切り分け）
2. HIGH 求積で同じ比較を回す（(c) の切り分け）
3. `--kli` と `--norel` でも回す（(a) の切り分け）

道具は `tools/gos_vs_zhang.py`（**2 つの規約がコードに固定してある** —
`q_au = q_Ang × a₀` と殻の規格化 `2(2l+1)/(2j+1)`）。

### P4. `s_cert` と `s_kin` の契約を分離

消費側は現在この 2 領域を同じ「0 + ε」で扱っている:

- **`s_cert < s ≤ s_kin`** — 物理的には可能だが**未収録**。ε で上界を宣言するのが正しい
- **`s > s_kin`** — **運動学的に不可能**（Ewald 球上にそのビーム対が存在しない）。
  「0 ± ε」ではなく**「その要求は成立しない」**と返すべき

⚠ **単独ファイルでは済まない。**一組で扱うこと:
生成 JSON への `s_kin` 契約化 / `schema/temari_dataset_v2.schema.json` /
`tools/temari_contract.py` / `tools/check_tables.jl` /
ReciPro 側 loader・`Evaluate` / `EdxCheck` / `AlchemiCheck`。

**既存データとの互換方法と schema_version 更新の要否を先に決める。**
実害は小さい（μ builder は実在のビームから ΔG を作るので s > s_kin を要求しない）。
