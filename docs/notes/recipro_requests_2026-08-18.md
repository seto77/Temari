# ReciPro から Temari への要望書 (2026-08-18)

*ReciPro に dataset-factors v1.0.0 (f_x / f_e) を組み込んだ作業から出てきた要望をまとめたもの。
ReciPro 側の設計正本は `ReciPro/.project-guidance/ReciPro/ReciPro_Temari散乱因子統合_指示書.md`。
契約テストの分解については別紙 `docs/notes/contract_conformance_split_2026-08-18.md`。*

**⚠ これは要望であって仕様ではない。** 優先度も ReciPro 側の都合による評価で、
Temari の科学的価値の順位とは別物 (例: GOS はロードマップで最重要級だが、ReciPro には
今のところ消費先が無いので下位に置いている)。

## 0. 現状 — ReciPro が Temari から受け取っているもの

| データ | 版 | ReciPro での使途 |
|---|---|---|
| F(s, E₀) イオン化形状因子 | dataset v5.0.0 | STEM-EDX / ALCHEMI (出荷済み) |

実装済みの 6 出口のうち **公開データセットになっているのはこの 2 つだけ**で、
`mott` / `phase` / `gos` / `edge` は「計算できるが出荷物が無い」状態。
以下の要望はほぼ全部「出荷してほしい」か「新しい出口が欲しい」のどちらか。

## P1 ★ Mott 弾性散乱のデータセット化 (`mott` 出口。実装済み → 出荷)

**いちばん効く。ReciPro が現に詰まっている問題を直接解く。**

### ReciPro 側の消費先
- `Crystallography/EBSD/MonteCarlo.cs` — EBSD の電子飛程モンテカルロ (本命)
- FormBeamInteraction の Attenuations & Transport タブ — σ_el、弾性 MFP

### 何が詰まっているか
現行は NIST SRD 64 (ELSEPA/Salvat 計算値を NIST が配布) の **sampler** を
`Atom/NistElastic/NistElasticPchip.bin` (2.1 MB) に圧縮して使っている。ところが
**NIST の sampler は 20 keV が上限**で、それを超えると screened Rutherford へフォールバックする。
フォールバックの transport 断面積は Mott の**約 1/10** (前方散乱過剰) なので、
後方散乱係数 η と侵入深さを過小評価する。**EBSD の常用加速電圧 25 / 30 kV はこの領域**に入る。

既存の解決案は「NIST のサイトから DCS を Playwright でスクレイプして自前で CDF を作り直す」
という重い経路で、着手されないまま止まっている。
**Temari なら任意エネルギーで自前計算できるので、この経路がまるごと要らなくなる。**

### ★ 先に解いてほしいブロッカー
ロードマップに書かれているとおり、**Temari の σ_el は NIST SRD 64 に対し 1 keV 以上で 0.90–0.94**。
これは無視できる差ではない (η は σ_tr に効くので数 % の差が効く)。
そして原因はおそらく既知で、**散乱ポテンシャルの定義の違い**だと思われる:

- Temari は「入射電子が感じる場ではない」として**純静電**に保つ方針 (交換を足すと σ_el が 1.6–4.9 倍に膨らむ)
- NIST = ELSEPA は交換 + 相関分極ポテンシャルを含む

つまり 0.90–0.94 は**バグではなく処方の違い**の可能性が高い。**この差の由来を特定し、
「どちらが何を含む量なのか」を明文化してもらえると、ReciPro 側は判断できる。**

→ 当面 ReciPro が望むのは **NIST の置き換えではなく「第 2 の出典として並べて比較できること」**。
FormBeamInteraction で今日 Waasmaier–Kirfel と Temari を並べたのと同じ形にしたい。

### 出荷してもらう形についてのお願い
- ⭐ **dσ/dΩ だけでなく、cos θ の累積分布 (CDF) まで出してほしい。**
  ReciPro のモンテカルロは NIST sampler と同じ「**cos θ = +1 → −1 を 0.001 刻み、2001 点の CDF**」
  ＋ σ_el を食う形になっていて、既存の PCHIP 圧縮パイプラインがそのまま使える。
  dσ/dΩ だけだと ReciPro 側で角度積分と逆関数化をやることになり、**前方ピークの求積が
  ReciPro 側の精度責任になってしまう** (そこは Temari の土俵のはず)
- エネルギー範囲: **50 eV–30 keV は必須** (これで EBSD の実用域が埋まる)。
  可能なら 300 keV まで伸ばせると TEM 側 (Attenuation タブ) でも使える
- 元素: **Z = 1–96** (現行 NIST 表と同じ範囲) あると差し替えが素直
- ⭐ **Sherman 関数 S(θ) は NIST 表に無い**ので、これは純粋な新規価値。
  ReciPro に今すぐ消費先は無いが、出せるなら一緒に入れてほしい

## P2 ★ イオンの f_x / f_e (未実装。factors v2 相当)

**今日入れた機能の最大の制約をそのまま外せる。**

dataset-factors v1.0.0 は**中性原子のみ**で、「イオンはこの表からは導出できない」と明記されている。
そのため ReciPro では、Temari を選ぶと**イオンサイトの曲線と値が消える**。
中性値で代用することも Peng 型の Mott–Bethe 単極子を足すことも禁じられているので (正しい判断だと思う)、
GUI には「Temari は中性原子 Z = 1–86 のみ」という注記を出して逃げている。

ReciPro の現状 (Temari 以外の出典):
- X 線: Waasmaier–Kirfel がイオンのパラメータを持つ (Z = 1–98)
- 電子線: Peng のイオン係数 + `MottBetheMonopoleCoefficient·ΔZ/s²` の単極子加算という近似

→ **第一原理のイオン表があれば、この近似を出典で置き換えられる。**

### 設計上あらかじめ潰しておきたい点
- **規格化が変わる**: 中性は f_x(0) = Z だが、イオンは f_x(0) = Z − q になる
- ★**f_e が s → 0 で発散する** (Mott–Bethe の分子が Z − f_x → q で残るため)。
  現行の契約「t = s² 上の not-a-knot 3 次スプライン、定義域 [0, 6] 両端含む」は
  **そのままでは使えない**はず。発散項を解析的に括り出した形 (例: f_e − C·q/s² を表にする) など、
  **契約の形から設計し直しになる**。ここは ReciPro 側の都合ではなく Temari の設計判断
- 収録するイオン種: ReciPro が実際に扱えるのは Peng / Waasmaier–Kirfel の表にある価数なので、
  **まずその集合に揃えてもらえれば十分**。全価数を網羅する必要はない

## P3 TDS 吸収形状因子 (未実装・ロードマップでは中工数)

ReciPro の `BetheMethod` は動力学回折で**吸収ポテンシャル (虚部) を非局所形式**で計算しており、
その高 q 側の扱いは現在進行中の課題になっている。**ReciPro 固有の痛みに最も直結する未実装項目**。

ただし要望としてはまだ粗い。**まず「どの規約に対応する量なのか」の定義合わせから**始めたい:
Bird–King / Weickenmeier–Kohl / Hall–Hirsch のどれに対応する量を出すのか、
あるいはそれらとは別に「第一原理の TDS 吸収形状因子」を定義するのか。
ここが決まらないと ReciPro 側は受け取れない。

---

## P4 Compton 散乱関数 S(q) (未実装・中工数)

FormBeamInteraction の `F(q)+S(q)` モードは現在 **xraylib** の `IncoherentSF` を使っている。
Temari 版があれば、f_x と同じく「出典を切り替えて比較できる」形にできる。
P1 / P2 ほどの実害は無いが、**f_x と同じ SCF 密度から出るので追加コストが小さいはず**という点で筋が良い。

---

## P5 光イオン化 σ_nl(ω) / ΔSCF 束縛エネルギー (未実装・中工数)

- **光イオン化断面積** → X 線の質量減衰係数 μ/ρ の光電項。現在は xraylib (NIST XCOM / FFAST 系)
- **ΔSCF 束縛エネルギー** → 吸収端エネルギー。現在は xraylib の表

どちらも「動いているものを置き換える」話なので優先度は低い。ただし**吸収端エネルギーは
STEM-EDX / EELS の定量で効く量**なので、第一原理値があること自体に意味はある。

## 当面は要らないもの (Temari 側の優先順位を下げてよい、という意味)

| 出口 | 理由 |
|---|---|
| GOS / Bethe 面 (`gos`)、EELS コアロス (`edge`) | **ReciPro に EELS モジュールが存在しない**。新機能を作るなら材料になるが、今は消費先が無い。⚠ 科学的価値が低いという意味では全くない — ReciPro に受け皿が無いだけ |
| 弾性位相シフト (`phase`) | Mott (P1) の下請けとしては要るが、単独の消費先は無い |
| 異常分散 f′, f″ | xraylib で足りている (構造因子への組込みも済んでいる)。大工数に見合う ReciPro 側の利得が今は無い |
| 蛍光収率・オージェ | **Temari が明示的にスコープ外**としており、ReciPro も異論なし。Fluorescence タブは xraylib のままでよい |

## 横断的な要望 (どの出口にも共通)

1. ★**「行ごとの保証範囲」を入れてほしい。** F(s, E₀) v5 には `s_cert` (行ごとの保証上限) があり、
   ReciPro のリーダーはそれを見て打ち切り・例外を出し分けている。**factors v1 には対応物が無い**ので、
   ReciPro 側は「定義域 [0, 6] の外は例外」という粗いガードしか書けていない。
   Mott やイオン表でも、**どこから先が埋め草なのかがデータに書いてある**と、消費側のガードが素直に書ける
2. **出荷形式は 1 元素 1 ファイルの JSON で十分。** ReciPro 側で `.bin` に詰め直すので、
   Temari が配布形式を作り込む必要はない (今回の f_x / f_e もそうした)
3. ⚠ **DOI**: dataset-factors v1.0.0 は**未発行**。ReciPro のマニュアルから出典として引用するので、
   DOI があると引用が安定する。F(s, E₀) 側 (10.5281/zenodo.21872050) と揃うのが望ましい
4. **契約テストを「補間規約の適合」と「値の同一性」に分ける** → 別紙 `docs/notes/contract_conformance_split_2026-08-18.md`。
   本要望書の中では**唯一 ReciPro 側がブロックされていない項目**で、優先度は低い
