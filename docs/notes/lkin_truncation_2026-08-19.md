## 3. 読み (何が言えて、何が言えないか)

- **言える**: 出荷 F(s) の M 殻チャネルは、src の部分波打ち切りの選び方 (m = min(r_core, 6/Z)) に
  **~1e-03 (絶対、s ≤ 0.5) 感度を持つ**。収束の向きは pilot §3 の 1 ノード掃引 (l_max を 18 → 80 で単調に
  +7.3 % → 飽和) から、`:kappa_rc` 側が収束側。K 殻は無傷、重元素の L3 は 1e-05 級
- **言えない**: `:kappa_rc` が最終値であること (κ·r_core + 12 のマージンは 1 ノードでしか検めていない。
  l_max をさらに振って確認すること)。真値との距離 (これは処方差)
- **なぜ今まで見えなかったか**: 収束監査 (`gen_production audit`) は `l_cap` を振った (128 → 160) が
  **l_kin < l_cap なので効かない**。ビット同一の規律は処方を固定する。外部比較 (µSTEM/OA、Zhang GOS) は
  K/L が主で M4/M5 は参照が薄い。[[self-convergence-underestimates]] の親戚 = **振っていないつまみ**
  ([[convergence-test-blind-axis]])
- **観測量へ**: s < 0.5 の伝達係数は ~1 (observable_propagation §4) ⇒ **M 殻チャネルのサイト比に ~1e-03**。
  v3→v5 の処方差 (direct 2.45e-03) の半分の桁

## 4. 対処 (★ 作者判断)

1. **今の出荷データは直さない** (src 凍結)。**MANIFEST v5 と data.md の誤差予算に「M 殻の部分波打ち切り感度
   ~1e-03 (絶対、s ≤ 0.5)」を KIND = prescription sensitivity として追記**する (出荷後の追記節)
2. **F v6 の台帳の先頭へ**: `l_kin` の m を軌道の広がりに基づく値へ (例: m = r_core、または 90 % 含有半径)。
   費用: 部分波数が高 ε で数倍 (Xe M4: 18 → 138、Ca M1: 73 → 128 cap)。⚠ 低 ε に高 l を強いると Coulomb
   関数が DomainError で落ちる (Fe K、l=42、pilot §3) ので κ に比例する形のまま
3. **σ(β,Δ) 候補 v2** は tools 側で `:kappa_rc` 相当を採る (Bote 規格化の分母 N(0) が 1e-03 動くため)
4. 次に測る: κ·r_core + 12 が収束か (l_max を +20/+40 でさらに振る、全 ε) / M1–M5 × 全 Z × 代表 E₀ の
   N(0) と F(s ≤ 2) の差の分布 (`lkin_truncation_probe.jl --rows` で回せる。1 行 10–30 s)
