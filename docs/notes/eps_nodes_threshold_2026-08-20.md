## 2. eps_nodes の構造 (src/l5_channel.jl:19)

3 区間: ① ε ∈ [0, E_th] を ε = E_th·x² (√ 変換、n1 点 GL) ② ε ∈ [E_th, (D+E_th)/2] を log 一様 (n2 点)
③ 上端を D−ε = scale·y² (n3 点)。D = ε_max = E₀ − E_th。低過電圧 (D ≤ 2E_th) は ①③ のみ。
HIGH の既定 = (n1, n2, n3) = (20, 56, 20)。

## 4. 読み (何が言えて、何が言えないか)

- **言える**: 出荷経路の ε 積分の n1 = 20 は、Z ≳ 78 の K 以外の副殻で量子化半歩を超える誤差
  (最悪 Rn M5 6e-05) を残す。n1 = 40 で M5/M2 は ≤ 2.5e-07 (n1 = 64 参照比、2 段の階段で加速収束)。
  この項は v5 の出荷データにも同一に存在する (ε ノードが同じなので)
- **言える (A3/A4、`../qcamp/eps_n1_verify.log`)**: n1 = 40 の残差 (n1=64 参照比、maxdF) は
  **Rn M5 2.5e-07 / M4 1.7e-07 / M3 3.0e-07 / M2 6.5e-08 / M1 7.1e-08 / L1 @45 3.1e-07 / L3 @100 3.0e-07 —
  全副殻で半歩の下** (n1=20 では M4 も 5.3e-05 と M5 並み)。Fe K (対照) は n1=20 で既に 1.0e-08。
  **実時間**: n1 20→40 (総 96→116) で 1 行 +0〜2 s (≈ +10 % 以下。M5: 15.9→13.2 s と逆転すらする =
  測定ゆらぎの内)、n1=64 (総 184) は ≈ +80 %。閾値近傍のノードが安い (κ 小 → l_max 最小) という見込みは実測どおり
- **参照の独立照合 (C、`../qcamp/eps_indep_ref2.log`)**: 区間 1 を **tanh-sinh (別の求積族、x = √(ε/scale)
  座標)** に置換した合成が、n1=64 の GL 参照と **Rn L1 @45 で相対 9.0e-12、Rn M5 @30 で ≤ 2e-06** (後者は
  TS 自身の h 収束 (0.12→0.08 で −3.4e-05 → +1.6e-06) が律速) で一致 — 参照は求積族に依らない
  (codex の「nested でない階段の一致は偶然相殺しうる」を閉じた)。
  ⚠ 照合器の最初の走行は **+10.6 % を出したがプローブ側のバグ** — 低過電圧 (D ≤ 2E_th ⟺ u ≤ 3) の行は
  eps_nodes が 2 区間分岐 (区間 1 のスケールが E_th でなく D/2) なのに E_th スケールで置換し、
  [D/2, E_th] を二重計上した ([[oracle-can-break-first]] の再演。修正 = `eps_indep_ref2.log`)。
  なお n1=40 の結論 (A3/A4) は両分岐の行 (L1 @45 = 2 区間 / M 殻 @30 = 3 区間) で確認済み
- **言えない**: **W (Z=74) と Rn (Z=86) を分ける微視的機構は未同定** —
  高密度スキャン B (`eps_integrand_scan.csv`、240 点 log 一様) では区間 1 の被積分関数は両 Z とも滑らか
  (極値 1、符号反転 0、l_max 階段も同じ 6..17) で、感度が 2000 倍違う理由は 10 点/桁の分解能では見えない
  (より狭い構造が節点間に落ちている可能性)。⚠ B の CSV はヘッダが `eps_keV` だが**値は Hartree**
  (ch.E_th の単位を取り違えた印字。解析には無影響 — 本書の keV 表記は換算済み)
- 区間 1 (ε ∈ [0, E_th]) は M5 @30 keV の N(0) の **≈ 68 %** を担う (Z=74 も 86 も) — n1 = 20 は
  「積分の 2/3 を 20 点で運ぶ」構成だった
- **なぜ v5 の監査で 6.8e-06 止まりに見えたか**: 監査の 8 ケースに Rn M5 が無かった (Au M5 @200 は
  ppw 系 1.1e-06 が最大)。[[convergence-test-blind-axis]] — 監査の標本が最悪行を含んでいなかった
- K 殻が無傷な理由は未同定 (閾値近傍の s→p 連続状態が滑らかという推測は書けるが測っていない)

## 5. 対処の候補 (作者判断 — `v6_spec_draft_2026-08-20.md` §0 判断 #2 を差し替える)

1. **HIGH v6 の n1 を 20 → 40 に上げる (全行一律)** — Z 閾値の overfit (codex の懸念) を回避でき、
   仕様も単純。費用: ノード数は 96 → 116 (+21 %) だが、**実測の実時間増分は +10 % 程度以下**
   (A3/A4。閾値近傍のノードは κ が小さく l_max が最小 = 1 ノードが最も安い)
2. 見送り + errata/数値誤差の内訳に記載 (v5 と同水準なので後退ではない。ただし v6 の重 Z では支配項が残る)
3. (参考) 当初案の「低 u 行だけ増強」は**的外れだった** — 層が u で切れないため

codex の助言 (機構特定を先に、Z 閾値を仕様に書かない、×2 の十分性は 2 段+独立参照で) は 1 で満たされる:
n1 は「どの行に効くか」を選ばず全行に掛かり、階段 (20→28→40→64) が 2 段の収束参照を与える。
⚠ 1 を採る場合、HIGH v6 の数値設定が再び動くので**監査の再実行と代表チャネルの再生成が要る** (§3.1 の手順に
織り込み済みの再実行と同時でよい)。
