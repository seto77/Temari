## 1. J とは何か

`σ(β, Δ)` という 1 つの数ではなく、**累積角度分布**

    C(β, ε) = ∫_{Ω(β)} d²σ/dΩdE dΩ        [nm²/Ha]

を β × ε の面として返す。ここから:

- 円形開口 = `C(β)`
- **同心環状開口 = `C(β_out) − C(β_in)`**
- 任意の**軸対称**検出器重み = θ 分解量からの後処理
- **B (`σ(β,Δ)` と k-factor) = この面の ε 窓積分**

## 2. 実測 1 — 面は何点で表せるか (`tools/j_surface_probe.jl`)

leave-out (格子を間引いて、抜いた点で内挿誤差を測る)。log–log の not-a-knot 3 次スプライン。

### 2.1 ⚠ 最初に私が測り方を間違えた (記録)

面全体で測ると誤差が **0.2〜4.0** と出て「面は表せない」に見えた。**誤りは私の重みの取り方**
— `値/最大` の「最大」を**行の最大値**で取っていたので、面全体では無視できる行が
「高重み」に見えていた。誤差の場所を出すと **ε = 30–75 keV 損失 × β = 280–413 mrad**
(面の 1e-03〜1e-06) という隅で、**EELS では誰も使わない**。

⇒ [[count-vs-weight]] の再演。⚠ **重みは必ず対象全体で取る。**

| β | 7 | 2.3 | 4.3e-02 / 1.2e-02 / **7.5e-02** |

⇒ **実用域なら 25 β × 33 ε (825 点) で ~5e-04**。⚠ **β 軸が律速**。

## 3. ★★★ 実測 2 — `σ(β,Δ)` はどの Q 帯から来るか

指示書は「A を B の前段に置く」としていたが、**B が尾根の Q に届いているかを誰も測って
いなかった**。ρ = Q/q_ridge の帯で σ の寄与を分けた (帯の区切りは
`docs/handover/next_phase_2026-08-13.md` §2 P3 と同じ。横断 on、PROD):

| チャネル | 条件 | ρ<0.3 | 0.3–0.8 | **0.8–1.5 (尾根)** | ≥1.5 |
|---|---|---:|---:|---:|---:|
| Fe K @200 keV | β=30 mrad, Δ=100 eV | 100 % | 0 % | **0.00 %** | 0 % |
| Fe K @200 keV | β=100, Δ=1000 | 61.0 % | 39.0 % | **0.00 %** | 0 % |
| Ag L3 @200 keV | β=100, Δ=100 | 64.3 % | 34.8 % | **0.85 %** | 0 % |
| Au M5 @200 keV | β=100, Δ=1000 | 66.6 % | 31.2 % | **2.16 %** | 0 % |
| Fe L3 @200 keV | β=100, Δ=1000 | 65.9 % | 28.2 % | **5.79 %** | 0.11 % |
| Au M5 @60 keV | β=100, Δ=1000 | 69.1 % | 30.9 % | **0.00 %** | 0 % |

**β ≤ 30 mrad では尾根帯は 0.00–2.42 %、ρ≥1.5 は最大 0.21 %。**

### 3.1 これが意味すること (と、意味しないこと)

- ⇒ **A の「原因究明」を B の blocking な前段から外してよい** (codex も同意)
- ⚠⚠ **「尾根の 36 % × 重み 5.8 % ≈ 2 %」は感度の見積りであって上界ではない** (codex の指摘)。
  理由: (1) 1.12–1.36 は**帯の代表統計**でセルごとの誤差上界ではない、
  (2) **ρ 0.3–0.8 が最大 39 % を運ぶのに、その帯での先方との一致を測っていない**
  (docs にあるのは ρ<0.3 と 0.8–1.5 だけ)、(3) 限られたチャネル・E₀・β・窓でしか測っていない、
  (4) 我々の重みで測った帯寄与と、先方側で積分した σ 比は厳密には同じでない
- ★ **代わりに置くべきゲート (codex 案。私も同意)**: **Zhang の GOS を同じ E₀・β・窓・
  横断項の規約で直接積分して σ 比を出す**。これなら ρ 0.3–0.8 を含む全域を一度に評価できる。
  差が許容内なら A の原因究明はリリースの blocker から外し、差が大きいときだけ
  ρ 0.3–0.8 のセル別残差を診断する
- ⇒ **「尾根の原因を解くまで B に進まない」は撤回してよいが、「外部比較なしで B/J を出す」
  は支持されない**

## 4. 構造的事実 — J の情報量は `S(Q,ε)` に等しい

コードから読める事実 (実測ではない):

- `eps_setup` が作る `RlTable` (= R_λ(Q)) は **E₀ に依らない**。引数の q 範囲は
  `k_i + k_f` に依るが、**関数そのものは (ε, 原子) だけで決まる**
- `legendre_sum!` が cosΘ=1 で返す `S(Q,ε)` も E₀ 非依存
- E₀ が入るのは **(a) 運動学の写像 Q(θ; ε, E₀)、(b) 位相空間因子 k_f/k_i、
  (c) 横断カーネル `coulomb_kernel(Q², ΔE, T₀)`** の 3 箇所だけで、**どれも解析的**

⇒ `C(β, ε; E₀)` は `S(Q, ε)` から解析的な運動学だけで生成できる。したがって:

| J の配り方 | 中身 | 評価 |
|---|---|---|
| `C(β,ε)` を (チャネル × E₀) ごとに配る | **~28 倍冗長** (E₀ の本数分) | 情報論的には materialized view。⚠ 「利用者の計算負担を減らす cache」としての価値は**あり得る**が、科学データセットの独自性としては弱い |
| compact に配る | **`S(Q,ε)` = GOS 表** | **却下した候補 F の復活**。Zhang の DB より狭い提案になる |
| **エンジンとして出す** | GOS/内部応答 → 実験幾何への写像器 | **F とは別物**。ここが J の居場所 |

⚠ **重要な例外** (codex): **有限 α の「干渉するプローブ」**では対角 `S(Q,Q)` では足りず、
**非対角 MDFF `S(Q₊,Q₋)`** が要る。そこまで含めれば J は**データ内容としても F を超える**。
⚠ **今回の実測からはそこまで言えない** (α=0 でしか測っていない)。

## 5. B と J の対比 (⚠ 私の初稿を codex が 2 点修正した)

| 軸 | B | J |
|---|---|---|
| 出力 | 指定した β・窓の σ、k-factor | `C(β,ε;E₀)` とその縮約器 |
| 利用形態 | 即用できる最終量 | 条件を後から変えられる応答エンジン |
| 柔軟性 | 指定済みの条件 | 円形・環状・滑らかな軸対称重み、任意窓 |
| 検証 | 外部の σ 実装と比べやすい | 面の補間・closure・縮約まで認証が要る |
| データ正本 | 数、またはオンデマンドの結果 | GOS/内部応答から生成する派生面 |

⚠ **私の初稿の誤り 2 点** (codex の指摘。実測とも整合する):

1. ❌ **「B は数を配るデータセット」** — B も CLI/API が条件ごとに数を返す形で成立する。
   **本質的な差は配布形式ではなく、縮約を計算時に確定するか利用者側へ遅延するか**
2. ❌ **「B は尾根に触れず J は触れる」** — §3 のとおり **B も条件次第で最大 5.8 % 触れる**。
   J も実用的な β・窓しか要求しなければ尾根をほぼ使わない。
   **違いは Q 帯ではなく、J が広い条件領域を公開するため尾根を含む要求も可能になる点**

## 6. J を看板にする場合、何を出荷するのか

⚠ **CLI + JSON だけだと「`edge` 出口へのオプション追加」に見えて看板にならない**
(私の懸念。codex も同意)。最小の一式 (codex 案):

- **安定した公開 API** — `response(channel, E0, …)` が面を返し、`circular` / `annular` /
  `window` / `kfactor` を**同じ応答から**計算できる
- **自己記述の response artifact** — メタデータは JSON、面本体は HDF5 等。β・ε 格子、単位、
  model id、横断項、閾値、精度の証明を同梱する。⚠ **網羅データセットではなく、
  再利用可能な計算成果物**として出す
- **目に見える参照ワークフロー** — 1 回の計算から開口・環状検出器・窓を動かすと σ と
  k-factor が即座に変わる notebook か小さな viewer
- **認証レポート** — 面 → B → 全角度総断面積の closure、格子誤差、窓の加法性、
  **Zhang を同条件で積分した比較**、計算時間と容量
- **小さな showcase pack** — Fe K / Ag L3 / Au M5 など数例だけ。⚠ **全面的な C データセットに
  しない**

看板名としては「角度–エネルギー面を配る」より、**GOS から実験幾何へ写す EELS response
engine** のほうが正確 (codex)。その中で **B = 標準定量モード**、**J = 応答面・検出器設計モード**。

## 7. 作者判断に要る軸 (codex の整理)

1. **想定利用者** — 即用の定量値が欲しい人か、検出器設計・条件探索をする人か
2. **待ち時間** — オンデマンド生成が対話的に許容できるか
3. **契約範囲** — α=0・軸対称までか、有限 α / 非軸対称まで目指すか
4. **外部接続** — eXSpy 等が読む GOS と、Temari 固有の response artifact のどちらを重視するか
5. **認証範囲** — 補間精度だけでなく、絶対 σ・横断項・端・窓・開口の物理精度をどこまで保証するか

## 8. 言えないこと

- ❌ **「面は認証済み」** — leave-out と `[0,100] eV` の 1 窓しか測っていない。
  **全窓・全チャネル・運動学端では未認証**
- ❌ **「A は不要になった」** — 外したのは **blocking な前段という位置づけ**だけ。
  代わりに**同条件で積分した σ 比**をゲートに置く必要がある (§3.1)
- ❌ **「B への尾根の影響は 2 % 以下」** — **感度の見積りであって上界ではない** (§3.1)
- ❌ **「ρ 0.3–0.8 は問題ない」** — **その帯での先方との一致を測っていない**。
  σ の 25–39 % を運ぶ帯なので、**測るまで何も言えない**
- ❌ **「J は B の完全な上位互換」** — α=0・軸対称の範囲では包含するが、
  **有限 α の干渉プローブは対角 GOS では足りない** (非対角 MDFF が要る)
- ❌ **「J をデータセットにできない」** — できるが、**28 倍冗長な view か、F の復活**の
  どちらかになる、というだけ。cache としての価値は否定していない
- ❌ **「E₀ 非依存だから E₀ ごとの再計算は無駄」** — 現行の実装は E₀ ごとに `eps_setup` を
  引き直しており、その**共有は候補 G (未実測、見積り 2.0–2.5 倍)**。別の話

## 9. 私の推奨 (作者判断のために)

**J を B の代替看板にせず、J を上位の製品概念、B を主要な縮約・実証ユースケースにする**
(codex の最終勧告。私も同意)。理由は §4 — J をデータセットにすると F に戻ってしまうので、
J の独自性は**エンジンとしての側面**にしかない。そして B はそのエンジンの
**最も直接的で、外部比較しやすく、小さく出荷できる**出力である。

**A は原因究明を前段から外し、代わりに「Zhang の GOS を同条件で積分した σ 比」を
リリースゲートに置く。**
