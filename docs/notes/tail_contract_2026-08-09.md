4. **基底は 1000 Bloch を想定**。1600 Bloch は実運用では重すぎるので設計目標に入れない

### なぜ 80 kV 下限が効くのか

s の上限は表の都合ではなく**運動学**で決まる。`l4_angular.jl:631` の
`kz = sqrt(k_i² − K²/4)` が実数である条件 `K < 2k_i` から

    s_kin = 1/λ   (λ = 相対論的電子波長)

⚠ **これは近似の限界ではない。**「Ewald 球上に差ベクトル K を持つビーム対が
存在しない」という幾何的な不可能性で、契約をどう書いても越えられない。

| E0 | s_kin [Å⁻¹] | 16 に対する余裕 |
|---:|---:|---:|
| 30 kV (表の下限) | **14.33** | **届かない** |
| 37.15 kV | 16.00 | 1.00 |
| **80 kV (ALCHEMI 下限)** | **23.95** | **1.50×** |
| 200 kV | 39.87 | 2.49× |
| 300 kV | 50.79 | 3.17× |

⚠ **表の E0 下限 30 kV は据え置く。**80 kV は ALCHEMI の下限であって、
通常の STEM-EDX 像は 30 kV でも使える。**通常の像は s ≤ 5.6 Å⁻¹ しか要求しない**
(`IonizationChannel.cs:527`、正典 SrTiO₃ 条件の実測) ので、低圧行が 16 に
届かないことは像側には一切影響しない。

### 低圧行の扱い — 行ごとの保証上限 + s ノードごとの補間基底

E0 < 37.15 kV の **1,491 行 (10.1 %)** は 16 Å⁻¹ に届かない。素朴に 0 で埋めると
**`GridAt(E0)` が s ノードごとに全 E0 行を PCHIP する**ため、200 kV の問い合わせが
30 kV 行の埋め草に引きずられる。したがって:

- 各行に **`s_cert` (運動学的保証上限)** を持たせる
- `GridAt` は **s ノード j で `s_cert ≥ s_j` の行だけ**を補間基底に使う
- 基底が問い合わせ E0 を含まないなら **throw** (= 物理的に不可能な要求。
  黙って値を返さない)

⚠ **この除外は限定的**である。発生するのは **321 ノード中の上位 34 点
(s > 14.33、グリッドの 10.6 %)** だけで、そこでも除外は 3.5–10.1 % の行:

| s [Å⁻¹] | 運動学的に不可な行 |
|---:|---:|
| 14.35 | 525 (3.5 %) |
| 15.00 | 727 (4.9 %) |
| 16.00 | 1,491 (10.1 %) |

**ALCHEMI (E0 ≥ 80 kV) は全 321 ノードで基底に入る**ので throw は起きない。
**通常の像 (s ≤ 5.6) は全行が有効**なので現行と同一の挙動になる。

### コスト (§2 の 12 Å⁻¹ 前提から更新)

161 → **321 点**。行重み付き scaling 係数 f = 0.277 (実測) から倍率 **×1.28**、
5h16 に対して **約 6h45**。ε 実測を足して **7h 前後**を見込む。
.bin は 2.64 MB → **約 3.4 MB**。

# s > s_max 契約の決定書 — ReciPro 要件 3-c への回答

作成日 2026-08-08 / 対象 = dataset v4.0.0 (525ch, 14,796 行) と ReciPro formatVersion 3

## 0. 結論(先に)

**(A) を主、(B) を残差の宣言として併用するハイブリッド。同時に既存の指数 tail を撤回する。**
具体的には ① s グリッドを 12 Å⁻¹ (241 点) へ延長して全再生成、② 各行に **実測した上界 ε** と **保証上限 s_cert** を付ける、③ `tail_fit` の a·exp(−b·s) を出荷形式から取り除く。dataset **v5.0.0** / formatVersion **4**。実測コストは生成 **約 6h15–6h30**(v4 の 5h16 比 ×1.19–1.23)、埋め込み .bin **+0.38–0.45 MB**(2.64 → 約 3.0–3.1 MB)。

(B) 単独(CPU 0 円)を採らない理由は 1 つだけ、**s∈(8,12] で切り捨てる量が小さくないから**である。実測で L1 は s=8 で |F| がまだ 3.6e-2 あって**上昇中**、Au L3 @300 kV は |F(12)|/|F(8)| = 0.24。ReciPro から μ_hg レベルの誤差予算が出ていない以上、この量を 0 にして「誤差は ε です」と言う契約は、害が測れないまま害を押し付けることになる。

## 1. 今日なにが壊れているか

出荷 v4 の 14,796 行のうち **6,359 行 (43.0 %) が `tail = null`** で、C# リーダーは s > 8 Å⁻¹ を要求されるとその行で `InvalidOperationException` を投げる (`IonizationChannel.cs:866`)。原因は `gen_production.jl:256-267` の `tail_fit` が **末尾 6 点が正・狭義単調減少・b>0** を全部要求するのに、F(s) が高 s で符号反転するからである。null 行の **91.6 % (5,826/6,359) が s≤8 内でゼロ交差**しており、拒否理由の内訳は「6 点中に非正あり」86.3 %、「正だが単調でない」13.7 %。殻別 null 率は K 0 % / L1 26.3 / L2 52.4 / L3 69.5 / M1 1.0 / M2 27.5 / M3 35.8 / M4 87.3 / M5 85.3 で、l が上がるほど悪い(始状態 l が大きいほど λ の本数が増え、干渉するファミリが増えて節が増える。`l3_radial.jl:27-28`)。

ReciPro が報告した「2150/4725 欠落」は**行数ではなく 9 点の E0 プローブ数**である(`AlchemiCheck/TailSurvey.cs:26` の既定 `--e0 60,80,...,400`)。この 9 点を Temari の JSON に当て直すと表の全セルが一致再現される(K 405/405, L1 483/603, …, M5 63/486, 合計 2575/4725)ので、要件の記述自体は正しい。ただし **survey は表の約 30 % しか歩いていない**: M1 は「513/513 充足」と出るが実際には 16 行 (Z=76..85, E0=30–35 kV) が null であり、L1 の max|F(8)| も真値は 3.61e-2 (Z=66 @30 kV) で報告値 2.68e-2 より 35 % 大きい。さらに**9 点はすべて生産 E0 格子のノードに一致する**ので、`TryGetTailB` の PCHIP 分岐 (`IonizationChannel.cs:806-820`) はこの検査で一度も踏まれない。任意 E0 での実カバレッジは 53.6 % しかない。

そして最も重い事実は、**既にある 8,437 本の tail が s=12 で当てにならない**ことである。Au L3 @300 kV は tail 検査を通っていて b̂=1.2704 が入っているが、s=12 で shipped tail は **+4.151e-5**、実際に計算すると **−1.615e-3** — **符号が逆で 39 倍小さい**。表内で同じ到達倍率 (×1.5) の外挿を検証すると、tail を持つ行のうち符号を外す割合が L2 23.5 % / L3 32.1 % / M3 24.3 %。つまり今日の状態は「43 % が hard fail、残り 57 % のうち高 l は静かに間違った符号を返す」である。

## 2. 推奨と、その根拠となる実測コスト

### 採るもの: (A) 12 Å⁻¹ 延長 + (B) 実測 ε

| | CPU (生成) | .bin | ReciPro 側改修 | s∈(8,12] で返る値 |
|---|---|---|---|---|
| (A) 単独 | ×1.138 → **5h59** | +0.38–0.45 MB | 必須 | 表の値そのもの |
| (A) splice のみ | ×0.862 → **4h33** | 同上 | 必須 | 同上(ただし台帳が要る) |
| (B) 単独・既存データから ε | **0** | +0(tailA 流用) | 必須 | **0**(誤差 ≤ ε) |
| (B) 単独・実測 ε | ≈(A) と同額 | +0 | 必須 | 0(誤差 ≤ ε) |
| **推奨 (A)+(B)** | ×1.19–1.23 → **6h15–6h30** | +0.38–0.45 MB | 必須 | 表の値 + s>12 は 0±ε |

**(A) が高くない理由**。1 行のコストは s ノード数に対して t = A + B·n で、**s に依存しない床 A が 62–72 %** を占める(Fe K 200 kV: A = 5.52 s / t(161) = 7.76 s。独立再測でも A/t(161) = 0.722)。RlTable と Dirac 連続状態は K 非依存で eps ノードごとに 1 回しか回らず、s と一緒に伸びるのは角度積分だけ(実測の scaling 比 f は M1 0.12 〜 Au M5 0.40、行重み平均 0.277)。行重み付き倍率は **×1.138**。

**ε を測るコスト**。0.25 刻みの粗い延長格子を 12.25 Å⁻¹ から `min(20, 0.98·s_kin)` まで回す(400 kV で 32 点、30 kV で 8 点)。B = 0.014–0.022 s/node なので **+5〜8 %**。これが (A)+(B) の ×1.19–1.23 の内訳である。

**(B) 単独を退ける理由(数字)**。切り捨てる量が小さくない。① 14,796 行中 **1,884 行 (12.7 %) が s=8 で |F| 上昇中**(L1 489, L3 360, M5 227, M4 205, K 0)。Dy L1 @30 kV は 3.609e-2 → **3.891e-2 (+7.8 %) @ s=8.85**。② tail を持つ行でも |F(12)|/|F(8)| は Fe K で 0.218、Au L3 で 0.24。**s=8 で 0 にすると (8,12] の寄与を丸ごと落とす**。③ ReciPro からは μ_hg レベルの誤差予算が提示されていない。予算が無い状態で「0 にして ε を報告する」は、害の大きさを検証できない契約である。

**(A) の副作用として大きい利得**が 2 つある。第一に、s ≤ 12 では `Evaluate` が tail 分岐に**入らない** (`IonizationChannel.cs:857-866`) ので、上に書いた「符号が逆の tail」も「E0 軸で b̂ を PCHIP する」経路も **要求域から丸ごと消える**。第二に、延長領域は数値的にむしろ安全側である(§4 参照)。

### 採らないもの

- **(C) |F| に当てて符号付きアンカーを格納する案**(リーダーは符号非依存なので形式変更ゼロで 2150 → 648 に減る)。**採ってはならない。** s=12 で直接計算した F と比べると比 0.449–4.187、**13 行中 2 行で符号が逆**(Au L3 @300 は +4.15e-5 vs 真値 −1.615e-3、Rn M5 @100 は −1.09e-4 vs +2.28e-5)。これは「合格判定を満たすために嘘をつく」経路であり、hard fail より悪い。
- **splice(s>8 だけ計算して貼る)**。1h26 しか安くならないのに、「どの行が出荷値のままでどの行が再計算か」の台帳が要り、後述の 72 行の扱いが別枠になる。**全再生成を選ぶ**。

## 4. Temari が s > s_max について正直に保証できること / 主張してはならないこと

### 保証できる

- **s ≤ 12 Å⁻¹**: 表の値そのもの。誤差は s 方向 PCHIP と E0 補間だけ。E0 の LOO は `check_tables.jl` C6 で新格子でも測り直す。
- **延長域の求積収束**: ⚠ ただし**数値は測り直してから書く**。`gen_production.jl:541-550` は **3 ケース × 7 つまみ**で定義されているのに、調査は 2 ケース × 5 つまみで回っていた(ppw / dt_log / **Au M5 @200 のケース**が抜けていた)。抜けを埋めた実測では **s>8 の最悪は Au M5 @200 の eps ノード ×1.4 で 3.22e-07 絶対**(ppw も Fe K で 6.69e-08)。⇒ **数値床は 1e-6 絶対**(実測最悪の約 3 倍)を提案する。
- **s > 12 の上界 ε**: 0.25 刻みの延長格子上の sup|F| に余裕係数を掛けた**実測値**。格子解像度ぶんの余裕は放物線当てで 3.2e-5 相対しか要らないので、係数は **E0 軸のために取る**。ε を bracketing 行の max で取る規則は**そのままでは上界にならない** — 出荷格子上の代理量で leave-one-out すると **13,746 行中 665 行 (4.8 %) で破れ、最悪 1.55 倍**(M4/M5)。⇒ **max × 2.0** を契約とする。
- **運動学的天井**: `l4_angular.jl:631` が `K >= 2·k_i` を明示的に error にする。`K = 4π·s·a0`(`l5_exit_edx.jl:39`)なので **s_kin = 1/λ** = 14.33 (30 kV) / 18.67 (50) / 27.02 (100) / 39.87 (200) / 60.83 (400) Å⁻¹。**S_req = 12 は全出荷 E0 で内側**だが、30 kV では余裕 1.19 倍しかない。**これが 12 を選ぶ物理的な理由**であって、16 は 30 kV で取れない(§5 R2)。なお 30 kV の s=12 は 2 本の Bloch 波が 114° 開いた配置で、数学的には定義されるが物理的には空虚 — MANIFEST に書く。

### 主張してはならない

- ❌ **「s > s_max で F は指数減衰する」**。Fe K @200 の局所レート b は 4→6 の 0.595 から 16→20 の 0.175 まで落ちる。`tail_fit` は 6 点の単調性しか見ておらず、**指数モデルそのものは一度も検査されていない**。
- ❌ **「べき則 s^-3 〜 s^-5」**。⚠ これは査読で否定された。局所最大どうしを結んだ包絡の実測指数は 12 行で **1.05〜18.2** に散る(Au L3 は 2.16、11.65→20 では 1.05、Rn M4 は 7.6 → 18.2 で加速)。3〜5 の帯は K (l=0) の観測を l>0 に一般化したもの。書くなら「代数的に減衰するが指数は行ごとに散る(実測 1〜18)」まで。
- ❌ **「|F(s_max)| が上界」**。14,796 行中 **1,884 行 (12.7 %)** が s=8 で上昇中。Dy L1 @30 kV は s=8.85 で +7.8 %。
- ❌ **「ε は E0 で内挿してよい」**。内挿した上界は上界ではない。max を取り、係数 2.0 を掛ける。
- ❌ **「符号は最後の点から引き継げる」**。延長した 12 行のうち **2 行が (8,12] 内に新しいゼロ**を持つ(Au L3 @9.32、Rn M5 @11.57)。(8,20] まで見れば 5 行。
- ❌ **「既存の 8,437 本の tail は 12 Å⁻¹ まで信用できる」**。Au L3 @300 は符号が逆で 39 倍小さい。K でも 12 で 0.558 倍(44 % 過小)。**これらは近似ですらなく、上界でもない**(s≤7 で当て直して (7,8] を検査すると、上界になっているのは K 1409 行中 665 行 = 47 %)。
- ❌ **「ε は M4/M5 の 1e-8 級の値まで意味を持つ」**。Au M5 @200 の (8,20] では |F| が 7.06e-8 まで落ちる一方、求積誤差が 3.22e-07。**s ≳ 15 の M4/M5 は雑音**。ε は床で出し、値としては出さない。
- ❌ **「延長は append なのでビット同一」**。物理入力は 14,724 行で同一だが、**出力は BLAS gemv 起因で 1 ULP 動く**(§3.4)。

## 5. リスクと、推奨を変える条件

**R1. 合格判定の書き換えに ReciPro 側の同意が要る。** `AlchemiCheck tail` は `!TryGetTailB` を測っており、**「throw しないか」を一度も測っていない**(s>s_max を全く探査していない: `TailSurvey.cs:62`)。したがって **(A) を採っても (B) を採っても、判定を書き換えないと「欠落 0」にはならない**。これは (A) の欠点ではなく、どちらにも共通の前提。加えて `IonizationChannel.cs:599` が 161 点以外を拒否する以上、**ReciPro 側の改修は選択肢によらず必須**である。同意が取れない場合に「(C) 符号付きアンカー」で 2150→648 に見せかける経路が存在するが、§2 のとおり **s=12 で符号を外すので採ってはならない**。

**R2. S_req = 12 で足りるか。** ALCHEMI の要求 s は基底依存(max|q+g_i−g_j|/2)で、1600 Bloch で 10.54 Å⁻¹ という実例がある。12 は余裕 1.14 倍しかない。**しかし 16 は取れない** — 30 kV の運動学的天井 14.33 を超え、低 E0 行だけ格子が短くなって C# の固定 sCount 契約と衝突する。**12 は天井の下に収まる最大の切りの良い値**。これは推奨を変えるどころか固める。もし作者が「30 kV を出荷から落として 16 Å⁻¹ にする」を選ぶなら、コストは ×1.30(321 点、実測)で +2 h、.bin は +0.8 MB 程度。

**R3. 生成中の GC クラッシュ。** v4 で 5 回(2 回 wedged)。`lane_watchdog.sh` 必須、15 分停滞で kill → 再起動。

**R4. 完走 ≠ 健全。** v4 では 3 本の破損行が生成ゲートを素通りし C11 が捕まえた。`is_sane_row` を足したが、**QC は必ず通す**。

**推奨を変える条件:**

1. **ReciPro が μ_hg レベルの誤差予算を出してきて、s>8 を 0 にする害がそれに収まると分かった場合** → (B) 単独(CPU 0)が最安になる。今これが決められないのは予算が無いからで、それが (A) を選ぶ最大の理由である。ただし L1 の 3.6e-2(F の正規化は F(0)=1)と Au L3 の 0.24 が既にあるので、収まる見込みは薄い。
2. **6 時間の再生成が飲めない場合** → splice (4h33) に落とす。差は 1h26 しかなく、72 行の別扱いと「どの行が出荷値のままか」の台帳を抱えるので、推奨はしない。
3. **延長した (8,12] を全 14,796 行で見て「ほぼ全行で |F| ≤ 1e-4」だった場合** → (B) 単独へ戻す余地。ただし L1 の 3.6e-2 が既に反例。

## 付録: 査読で否定され、この決定書が**依拠していない**主張

- 「s グリッドを延ばしても出荷値はビット同一」— **否定**。物理入力は 14,724 行で同一だが、出力は HIGH で約 1/3 の行が s=8.0 列で 1 ULP 動く。付随して「5.7e-5 は量子化 1e-6 の 57 倍」は**相対と絶対の取り違え**(真の max|dF| は 7.8e-7 = 量子化 0.78 個ぶん)。
- 「(C) 符号付きアンカーで足り、(A) は不要」— **否定**(s=12 で 13 行中 2 行が符号反転)。ただし同じ調査の「C# リーダーは符号非依存」「合格判定は throw を測っていない」「ε は max であって PCHIP でない」は生きており、本書はそれらに依拠している。同調査の「.bin が +1.3 MB になる」も**否定**(実測 +0.38 MB)。
- 「s>8 の求積誤差 ≤ 2.7e-8、数値床 1e-7」「包絡はべき則 s^-3〜s^-5」「ε は bracketing E0 の max で足りる」「新ゼロは 12 行中 6 行」— **すべて否定**。正しくは 3.22e-07 / 床 1e-6 / 指数 1〜18 / max×2.0 / (8,12] 内は 2 行。同調査の定性的結論(振動する・指数形は誤り・|F(s_max)| は上界でない・既存 tail は 12 で誤り・運動学的天井)は生きている。
- 「`gen_production.jl:264` の `b <= 0` は到達不能な dead code」— **否定**。厳密算術では到達不能で実測 0/14,796 だが、**浮動小数点では窓がほぼ平坦なとき到達する**(1 ulp 差の 6 点を食わせると b = 0.0 や −1.39e-11 を返す)。tail_fit ごと撤去するので実務上は消えるが、**「安全網だから消せる」と読まないこと**。
- 「tail が張れないのは減衰しないからではなく符号のせい」— 行数の話としては正しい(86.3 %)が、**|F(8)| ≥ 1e-2 の帯 511 行では 509 行が単調性で落ちており、符号は 2 行だけ**(全部 L1)。運用上の優先である L2/L3 では 2451/2451 が符号なので、要件の文脈では正しい。
