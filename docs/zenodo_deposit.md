# Zenodo への登録手順 (2026-08-10)

*データセットに DOI を付けて長期保存するための作業手順。次の世代でも同じ作業になるので、
貼り付け用のメタデータごと残す。*

---

## 0. Zenodo とは

**CERN のデータセンターが運用する、研究成果の公開リポジトリ**（InvenioRDM 基盤、
CERN・OpenAIRE・EU が資金提供）。無料で使えて、上げたものに **DOI** が付く。

GitHub release と何が違うのか:

| | GitHub release | Zenodo |
|---|---|---|
| 消せるか | **消せる・差し替えられる** | 公開後のファイルは実質固定 |
| 引用 | URL（repo が消えれば切れる） | **DOI**（永続識別子） |
| 保存 | GitHub の運用次第 | **bit-level での保存を保証**と明記 |
| 版 | タグ | **版ごとに別レコード**＋版どうしが相互リンク |

⇒ 論文から引用されうるデータは Zenodo を正本にする。GitHub release は**同一バイトの
ミラー**として残す（`make_dataset_release.sh` が決定論的に作るので、両者が同一である
ことを digest で示せる）。

⚠ **Zenodo が保証するのは bit-level 保存だけ**。「10 年後・50 年後に読めるか」は
形式の選択の問題なので、JSON（テキスト）で出しているのは正しい判断。

---

## 1. ⚠ 登録は 2 本立てにする

コードとデータで release を分けたのと同じ理由で、**Zenodo でも別レコードにする**。

| | 対象 | 方法 |
|---|---|---|
| **ソフトウェア** | リポジトリのスナップショット | GitHub–Zenodo 連携（自動） |
| **データセット** | `temari-dataset-vX.Y.Z.tar.gz` | **手動アップロード**（下記 §3） |

⚠⚠ **GitHub–Zenodo 連携はデータセットを保存しない** — 連携が保存するのは
**リポジトリの zip スナップショットだけ**で、**release の asset は含まれない**。
`prod*/` は .gitignore なので、連携に任せるとデータは 1 バイトも保存されない。
**データセットは必ず手動で上げること。**

---

## 2. ソフトウェア側（任意・自動化できる）

1. https://zenodo.org に GitHub アカウントでログイン
2. 右上メニュー → **GitHub** → リポジトリ一覧で `seto77/Temari` を **ON**
3. 以後、**新しく作った GitHub release** が自動で Zenodo へ保存され DOI が付く

⚠ **ON にする前の release は対象外**。v1.0.1 に DOI を付けたいなら、ON にしてから
release を作り直すか、手動で上げる。

⚠ メタデータは `.zenodo.json` があればそれが使われる（無いと GitHub の情報から
推測されて著者名やライセンスがずれることがある）。

---

## 3. データセット側（手動。これが本題）

### 3.1 上げるもの

```
dist/temari-dataset-v5.0.0.tar.gz          44.7 MB (46,835,345 bytes)
dist/temari-dataset-v5.0.0.tar.gz.sha256
```

無ければ `bash tools/make_dataset_release.sh` で作り直せる（**何度作っても同じバイト**）。

### 3.2 手順

1. https://zenodo.org にログイン（ORCID があれば ORCID で。著者同定が効く）
2. **New upload**
3. 上の 2 ファイルをドラッグ
4. §3.3 のメタデータを埋める
5. **Save** して内容を確認 → **Publish**

⚠⚠ **Publish するとファイルは実質固定される** — 間違えたら「新しい版」を作ることになり、
DOI が 1 つ無駄に増える。**Publish 前に必ず確認する。**

## 4. DOI が出たあとの作業

⚠ **相互記載しないと「どちらが正本か」が読み手に分からない**。次の 4 箇所へ:

1. `CITATION.cff` — データセットの DOI を `references` に足す
2. `docs/dataset_release_README.md` — 「Citation and licence」節へ DOI
3. GitHub release `dataset-v5.0.0` の説明 — 冒頭に「正本は Zenodo (DOI …)」
4. `src/prod_v5_jl/MANIFEST.md` — 配布先の記録

⚠ **DOI は 2 種類ある** — Zenodo は版ごとに別レコードを作り、それぞれ独立した
永続識別子を持ちつつ相互にリンクする。**再現性のために引用すべきは版の DOI**
（そのファイルが変わっていないことが保証される）。「このデータセット一般」を
指したいときだけ、全版をまとめる側の DOI を使う。

## 5. 次の世代でやること

```bash
bash tools/make_dataset_release.sh          # 決定論的に組む + 展開して自己検証
gh release create dataset-vX.Y.Z --target main --title "..." --notes-file ... \
   dist/temari-dataset-vX.Y.Z.tar.gz dist/temari-dataset-vX.Y.Z.tar.gz.sha256
```

そのうえで Zenodo のレコードで **New version** を押し、新しい tar.gz に差し替える。
⚠ **新規レコードを作らない** — 版どうしのリンクが切れて、同じデータセットの系列だと
読み取れなくなる。
