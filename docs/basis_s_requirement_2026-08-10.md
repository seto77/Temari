# 基底が要求する s の実測 — §1.2 scaling の裏取り (2026-08-10)

*`docs/next_phase_2026-08-10.md` §2.1-5 の実施記録。同§2 の残り 4 項目の事実確認も本書に置く。*

**結論を先に: S_req = 16 Å⁻¹ の判断は変わらない (余裕 1.52×)。ただし §1.2 の
scaling 式は 2 つの指数が実測と合わない** — 実害は無いが、これを根拠に
「将来 N を増やしたら 16 が埋まる」を語ってはいけない。

---

## 0. 測り方

`AlchemiCheck basis` を新設した (`tools/AlchemiCheck/BasisSurvey.cs`)。
測るのは `AlchemiBasisDiagnostic.MaxShapeArgumentAngstromInv` = **union の max|g|**
(ALCHEMI は μ_hg が 2 反射の差 ΔG = g_h − g_g で決まるので、要求 s = max|g|)。

⚠ **`Find_gVectors` は構造因子を見ない** (rating = |g|·q²、`BetheMethod.cs:4000` 付近)。
要求 s は逆格子の幾何と Ewald 球スクリーニングだけで決まるので、
**「a だけ違う P1 単純立方 1 原子セル」が Ni/Si の代理として正しい** (§1.2 の表と同じ扱い)。

配置依存が大きいので 2 通り測った:

| mode | 配置 |
|---|---|
| `zone` | 厳密な [001] 帯軸。surface ∥ c* なので接平面重複除去が HOLZ を畳む |
| `row` | x 軸まわり 17.3° 傾斜の h00 系統反射列 (`AlchemiCheck curve` と同配置) |

`row` を基準とする — **§1.2 の較正 3 点のうち 2 点を厳密に再現した**から
(N=800 → 8.43、N=1600 → 10.54。いずれも β-AlCo 250 keV)。
残る N=165 は §1.2 が 6.20、実測は `row` 7.21 / `zone` 5.78 で、
**この点だけ別配置で取られている**。

## 2. ⚠ §1.2 の scaling は 2 つの指数が合わない

`R ≈ 1.41 · k^(1/4) · a^(−3/4) · N^(1/4)` に対し、最小二乗の実測は

| | 指示書 §1.2 | 実測 `row` | 実測 `zone` |
|---|---:|---:|---:|
| k (= 1/λ) の指数 | +0.250 | **−0.003** | −0.159 |
| a の指数 | −0.750 | **−1.000** | −1.155 |
| N の指数 | +0.250 | +0.156 | +0.270 |

### 2.1 R は E0 にほぼ依存しない (最大の食い違い)

β-AlCo N=1600 で 80 → 400 kV は k が **2.54 倍** (23.95 → 60.83 Å⁻¹) 動くのに、
R は 10.54 → 10.54 と **0.4 % しか動かない**。§1.2 が予言する k^(1/4) = 1.26 倍は出ない。
他の 3 系でも同じ (Ni 8.54/8.56/8.56/8.54、SrTiO₃ 7.71/7.72/7.73/7.73、Si 5.54/5.54/5.55/5.55)。

⇒ **§1.2 の「小さい格子・高加速電圧ほど大きい」は半分誤り。**
小さい格子ほど大きいのは正しく (むしろ a^(−1) でより強い)、
**高加速電圧ほど大きいは成り立たない。**

### 2.2 a の指数は厳密に −1

N=1600 / 250 kV の `row` で R·a を取ると:

| 系 | a [Å] | R [Å⁻¹] | R·a |
|---|---:|---:|---:|
| β-AlCo | 2.861 | 10.52 | 30.10 |
| Ni | 3.524 | 8.56 | 30.17 |
| SrTiO₃ | 3.905 | 7.73 | 30.19 |
| Si | 5.431 | 5.55 | 30.14 |

**R·a = 30.15 ± 0.05 (0.15 %)。**a^(−1) がぴたりと合う。

### 2.3 なぜ §1.2 は外したか (責める話ではない)

§1.2 の較正 3 点は **N だけを振っていた** (β-AlCo 固定、250 keV 固定)。
だから k と a の指数は較正できず、`R_n = sqrt(2 n k H)` から**導出**するしかなかった。
§1.2 自身が「a^(-3/4) と k^(1/4) の指数は導出値で他系では未検証」と明記している。
本書はその未検証部分を埋めただけである。

## 3. 判断への影響: **無い (16 は据え置き)**

| | 値 |
|---|---|
| §1.2 が予測した最悪 (β-AlCo 400 kV, N=1600) | 11.30 Å⁻¹ |
| **実測の最大 (全 4 系 × 4 電圧 × N≤1600、両 mode)** | **10.54 Å⁻¹** |
| S_req = 16 に対する余裕 | **1.52×** (§1.2 の見積り 1.42× より広い) |

⚠ ただし**外挿の主張は差し替えが要る**。§1.2 は N^(1/4) から
「16 が埋まるのは N ≈ 6,400」と書いたが、実測 N^0.156 では **N ≈ 2×10⁴**。
どちらにせよ **ReciPro 側は N ≤ 1600 に制限した** (作者判断 2026-08-10、
`FormALCHEMI.Designer.cs` の `Maximum` 2000 → 1600) ので、
**GUI からは 16 Å⁻¹ を使い切れない**。これが最も強い保証である。

⚠ **N 依存は階段関数**である (基底が Laue zone 単位で太るため)。
実測でも N=400 と N=800 が同じ R を返す (8.43 / 8.43)。
`N^p` の当てはめは階段のならしであって、法則ではない。

## 4. §2 の残り 4 項目 — 事実確認の結果

すべて指示書の記述どおりだった (数値も再現)。

### 4.1 `AlchemiCheck tail` の合格判定 (§2.1-1)

- `TailSurvey.cs:53` は `!ch.TryGetTailB(e, out _)` を数えている = **b̂ が引けるか**
- `:62` の探査点は `SMaxAngstromInv * 10` nm⁻¹ = **s = 8.00 ちょうど**なので
  `Evaluate` の `sA <= SMax` 分岐に入る ⇒ **s > s_max を一度も踏んでいない**
- `:90` は無条件 `return 0`
- **★作者決定 (2026-08-10): ゲート化する。**判定を
  「`Evaluate` が s = 0…min(S_req, s_kin(E0)) で投げない」へ変え、
  全 E0 行 + オフノード掃引を歩き、欠落 > 0 で非零終了

### 4.2 既定 E0 9 点の被覆 (§2.1-2)

出荷 v4 の JSON に当て直した実測:

| 量 | 実測 | 指示書 |
|---|---:|---:|
| 9 点プローブが生産ノードに一致した数 | **4725 / 4725** | 「すべて一致」✓ |
| ノード上の tail 充足 | 8437 / 14796 = **57.0 %** | 8,437 本 ✓ |
| 任意 E0 (E0 区間長で重み付け) の充足 | **53.7 %** | 53.6 % ✓ |
| tail = null | 6359 = **43.0 %** | 43.0 % ✓ |

殻別 null 率も一致 (K 0 / L1 26.3 / L2 52.4 / L3 69.5 / M1 1.0 / M2 27.5 /
M3 35.8 / M4 87.3 / M5 85.3 %)。M1 の null 16 行 = **Z=76–85, E0=30–35 kV** も一致。

⇒ **オフノードが 0 件なので `TryGetTailB` の PCHIP 分岐はこの検査で一度も走らない。**

### 4.3 80 kV 下限をどこで担保するか (§2.1-3)

- **ALCHEMI 専用の電圧下限は現在どこにも無い。**電圧は
  `FormDiffractionSimulator.waveLengthControl.Energy` の共有値 (`FormALCHEMI.cs:40`)
- 唯一の境界は `IonizationDataProvider.MinE0KeV/MaxE0KeV = 30/400`
  (`IonizationChannel.cs:915`、`GridAt` :777 と `Resolve` :1030 で発火)
- **★作者決定: hard gate にしない。**§3.1 の `s_cert` 判定に任せる —
  80 kV 未満でも基底が s ≤ s_kin(E0) に収まる限り ALCHEMI は正しく動くので、
  電圧そのものを弾くのは過剰。80 kV は「16 Å⁻¹ を保証できる下限」として
  GUI 警告とドキュメントで宣言する

### 4.4 1600 Bloch (§2.1-4)

- `numericBoxMaxNumOfBloch`: `Maximum = 2000` / 既定 120、`AlchemiRequest` 既定 300
- 基底警告文 (`BetheMethod.Alchemi.cs:182`) とツールチップ (`FormALCHEMI.cs:169`) は
  **"8 Å⁻¹" 決め打ち** ⇒ v5 と同時に 16 へ直すこと
- **★作者決定 (2026-08-10): `Maximum` を 1600 にする** (実施済)。
  実測の最大要求 10.54 Å⁻¹ が N=1600 で出るので、ここで打ち切れば
  収録範囲 16 Å⁻¹ は原理的に使い切れない
