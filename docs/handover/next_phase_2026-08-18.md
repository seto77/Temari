## 2. ★ 看板: B = `σ(β, Δ)` と k-factor

**なぜこれか。** EELS 定量の利用者が最後に必要とするのは形状因子でも GOS でもなく、
「この収集角・このエネルギー窓で、この元素はどれだけ数えられるか」である。そこまで
出すコードは公開されていない。エンジンは必要な量を**組み立てられる**位置にある。

### 2.0 ⚠ 訂正 (2026-08-18) — 「`dNde` に角度分解がある」は誤り

本書の初版はここに「`edge` 出口が持つ `diag.dNde` は (ε ノード × K ノード) で、
K=0 に潰す前の角度分解がそこにある」と書いていた。**ソースを読み直した結果、誤りと
判明した**ので訂正する。

- `dNde[ie, iK]` の **K 軸は ALCHEMI の差ベクトル K = Q₊ − Q₋** (`F(s) = N(K)/N(0)`、
  K = 4πs) であって、飛来電子の散乱角ではない (`l5_channel.jl` の `compute_NK`)。
  `l5_exit_eels.jl` 自身が「`dNde[ie,1]` = K=0 の ε ノード ie における dN/dε」と
  書いており、**散乱角についてはすでに積分済み**である
- 本当の角度分解は `l4_angular.jl` の `angular_integral` の **K=0 分岐の x 求積**の中に
  ある。`AngWS` が `a = 4·k_i·k_f/(k_i−k_f)²` を係数として `x ∈ (0, log1p(a))` 上の
  Gauss–Legendre を張り、`t = expm1(x)/a = sin²(θ/2)`、`jac_t = exp(x)/a`、
  `cosθ = 1 − 2t` と変換している。K=0 分岐が返すのは
  `2π Σ_i wx[i]·2·jac_t[i]·Sv[i]/Q2[i]²` なので、**1 求積点あたりの寄与が
  d²σ/dΩdE に相当する**
- したがって θ ≤ β は **`x ≤ log(1 + a·sin²(β/2))` への求積区間の制限**に落ちる。
  ⚠ **既存ノードを `x ≤ x_β` で切り捨てるだけでは駄目** — GL の重みは全区間用なので、
  部分和は部分積分にならない。β ごとに部分区間の求積を張り直すこと
- コスト構造は追い風。律速は ε ノードごとの動径 R_λ(Q) 表の生成で、角度求積は安い
  ⇒ **1 回の ε 走査で多数の β を同時に出せる**。⚠ ただし β ごとに求積点が変わる以上、
  R(Q) の補間と Legendre 和は引き直しになる。**倍率は実測するまで言わない**
- ⚠ **エネルギー窓は角度より大きい仕事**。`l5_channel.jl` の `eps_nodes` は
  「全積分が速く収束する」ための 3 区間変換 GL (両端の √ 挙動を吸収する) なので、
  `[E_th+Δ₁, E_th+Δ₂]` は既存ノードの部分和では張れず、**窓ごとに専用の求積が要る**

⇒ **§2.2 のゲート「互いに素な 2 窓の加法性」は恒等式ではなく、許容誤差つきの検査になる。**
⇒ **P5 の「中程度の工数」は、角度部分だけなら維持できるが、製品としての `σ(β, Δ)` まで
含めると中〜やや大**。実測で確定させるのが S2 スパイクの目的 (§9)。

### 2.1 最小限の契約 (codex 案 + 私の整理)

**出す量**

| 量 | 備考 |
|---|---|
| `d²σ/dΩdE` | 二重微分断面積 |
| `dσ/dE` (開口積分後) | 既存の `edge` 出口の一般化 |
| `σ(β, [Δ₁, Δ₂])` | 部分断面積。これが本体 |
| k-factor | **向きを明示**: `k_{A/B} = σ_B / σ_A`、`C_A/C_B = (I_A/I_B)·k_{A/B}` |
| `sigma_own` と Bote 規格化版 | **黙って入れ替えない**。どちらで規格化したかを必ず出す |

**明示が要るパラメータ** — 曖昧にしたら契約として無意味になる箇所:

- 元素・副殻・占有数の規格化
- `E0`、閾値とその出所 (Bote 端か、自前の Dirac 固有値か)
- **β** = 軸対称の円形収集半角
- **α** = 収束半角。⚠ **v1 は α = 0 (平行照明) に限定する**。有限 α は
  「非干渉な角度平均」か「干渉するプローブ」かを決める必要があり、これは
  無害な追加パラメータではない。実装しないなら受け付けない
- エネルギー窓。**絶対損失ではなく `[E_th + Δ₁, E_th + Δ₂]` の端相対を推奨**
- 要求窓が計算済み ε 域を超えたときの挙動 (拒否か、切り詰めて宣言か)
- 横断カーネルの有無 (model id の `-TR`)
- 単位と数値認証のフィールド

⚠ **経験的なバックグラウンドモデルは契約に入れない。** 対応する実験量は
「同じ窓で背景を差し引いた計数」であると書くに留める。ELNES・白線・化学シフト・
多重散乱・検出器応答は範囲外であることも明記する。

### 2.2 外部参照が無くても効くゲート (これが設計の肝)

`σ(β, Δ)` には信頼できる絶対の外部基準が無い。だから**内部恒等式で締める**:

- 非負・有限
- `d²σ/dΩdE` を立体角で積分すると現行の `dσ/dE` に戻る
- それを ε で積分すると `sigma_own` に戻る
- β → 0 と窓幅 → 0 で 0
- β を広げる・窓を広げると単調増加
- 互いに素な 2 つのエネルギー窓の加法性
- 全角度・全エネルギーで総断面積に戻る
- Bote 規格化版が全域で Bote の σ に一致する — ⚠ これは**構成上の恒等式**であって
  検証ではない。そう書くこと
- `k_{AA} = 1`、`k_{A/B}·k_{B/A} = 1`
- 求積を細かくしても動かない (収束ゲート)
- 既存の T11b (水素 GOS 面) と T22b (横断カーネル) がそのまま効く

### 2.3 外部比較として何があるか (期待しすぎないこと)

| 相手 | 使い方 |
|---|---|
| Egerton の SIGMAK/SIGMAL | **旧実装との比較**。真値ではない |
| Leapman et al. (1980) の Hartree–Slater GOS | モデル比較 |
| Zhang et al. (2025) の Dirac GOS DB | **同じ β・同じ窓の規約で積分してから**比べる。現代の計算との比較 |
| EELS Atlas | 形状・立ち上がりには使えるが、絶対断面積の基準にはならない |

⚠ **「実験検証済みの k-factor」とは言えない**。開口分解された絶対 k-factor の実験値は
乏しく、背景・膜厚・検出器較正と絡み合っている。言ってよいのは
「**標準的な実装および現代の計算と突き合わせた**」まで。

### 3.1 ⚠ 私の案は 1 つ潰れた (記録)

「水素様イオン (He⁺, Li²⁺ …) なら厳密解があり、先方 DB は Z=1–108 を収録しているから、
尾根の誤差が Z とともに増えるかを見れば、標本化の artefact か多電子の物理かを切り分け
られる」と考えたが、**成立しない** — 先方が収録しているのは**中性原子**で、He や Li の
K 端は多電子中性原子であってヘリウム様イオンではない。**厳密な 1 電子比較ができるのは
中性 H だけ**。(codex の指摘。確認済み)

### 3.2 実際にやる順 (公開 DB と自前コードだけで足りる)

1. **厳密 H に対する残差の指紋を取る** — 「先方 − 厳密」を (ε, ρ) 平面に描く。次に
   Fe L1 / Au M5 の「我々 − 先方」の残差を無次元化して重ねる。**符号つきの形が似れば**
   共通の数値機構を示唆する。⚠ **示唆であって証明ではない**
2. **格子点そのものか、再構成かを切り分ける** — 先方の H の誤差が、収録された
   128×256 の**格子点上で既に存在するか**を見る。存在するなら消費側の内挿の話ではない。
   存在しないなら、厳密面を同じ格子へ間引いて再構成し、誤差が再現するかを見る
3. **局所の不連続を探す** — 先方の格子点上で我々を直接計算し、隣り合う ε 行と q の曲率を
   見る。応答が滑らかであるべきところに公開表が段差を持つなら、それは表化・書き出しの
   artefact の直接証拠になる (**Fe K1 の ε = 871.8 → 965.0 eV に実在する ~10 % の段差**が
   既にこの型)。⚠ ただし滑らかな全体バイアスの説明にはならない
4. **λ 分解して、held-out で予測する** — 我々の S を λ ごとに分け、定数 `c_λ` の組で
   先方を再構成できるかを見る。⚠ **同じデータに当てた fit を機構の同定と呼ばないこと**。
   Fe L1 の尾根の片側で合わせ、**反対側と Au M5 を予測**して初めて意味がある

**⚠ 尾根の両側に窓を持つのは Fe L1 と Au M5 だけ** (Fe K と Au L3 は片側しか含まないので
振幅と横ずれが縮退する)。測定はこの 2 チャネルに絞る。

### 3.3 何が言えて、何が言えないか

- λ の fit が**通った**場合に言えるのは
  「食い違いは multipole ごとの規格化ないし書き出し規約と整合的である」まで。
  **「先方の規約が誤り」とは言えない** (動径側の差がたまたま同じ形に因数分解しうる)
- **通らなかった**場合に言えるのは「一定の λ 倍率では説明できない」だけ。軌道・連続状態の
  規格化・内挿・閾値・λ 依存の数値誤差を区別しない
- **第三の物差しが無い以上、「物理的にどちらが正しいか」は決められない。**
  決められるのは**差がどの層に属するか**まで。メモにも論文にもそう書く

### 3.4 FAC を依存にするか — **しない**

codex の crossed-input 実験 (先方の軌道 × 我々の評価器、など 2×2) は理屈としては決定的
だが、**公開 DB に軌道もポテンシャルも位相シフトも入っていない** (`data` / `free_energy` /
`q` / `metadata/edges_info` だけ) ので、我々が FAC を建てて走らせる必要がある。

⚠ **設定を再現できないまま「何らかの FAC 計算」を作ると、2 つの答えを切り分ける代わりに
3 つ目の別設定の答えを増やすだけ**になる。方針:

## 5. C = イオン (次々世代の候補)

**独自性は高い** — 計算されたイオンの散乱因子を配っている人はいない。`SCFAtom` は任意の
占有数を受けるので、生成そのものは動く。参照も存在する
(Olukayode et al., Acta Cryst. **A79**, 293–304 (2023) = 論文 II、イオンの DHF f_x)。

curated なデータセットにする。最小スコープが見た目より大きいのはこのため。

## 6. 位置取り — Zhang et al. (2025) の EDS DB に対して

先方は Bloch 波/マルチスライス向けの Dirac ベース EDS データベースを公開すると予告して
いる (arXiv:2405.10151 §7)。**これは Temari の製品そのもの**。

**前面に出してよい差** (codex の整理に同意):

- 静的な表ではなく、**処方と中間量まで追える実行可能・監査可能な計算系**であること
- 対角 GOS だけでなく、**差ベクトル依存の MDFF** (ALCHEMI が要求する量)
- Bote–Salvat 規格化から `σ(β, Δ)`・k-factor まで、**用途に直結する出口**
- model id・schema・golden・負のテスト・数値予算を含む**再現性の契約**
- 弾性散乱因子と内殻電離を**同じ原子から**扱っていること
- 必要なら GOSH/GOS5 を読み書きして、既存の生態系と**競合ではなく接続**すること

**やめる主張**:

- 「唯一の」「最初の」Dirac EDS データベース
- 我々の GOS のほうが Zhang より正しい・高精度である
- s = 16 まであること自体が精度上の優位である
- KLI がイオン化について外部参照より正確である
- 完全な第一原理・実験検証済み・無調整である
- 現在の公開 GOS が対角であることを、**将来の EDS DB にもそのまま当てはめる**こと

⚠ **先方の DB が出たら、宣伝文を書く前に実物で形式・off-diagonal 対応・規格化・ライセンスを
確認する**こと ([[transcribed-formula-check]] と同じ理由 — 論文本文と公開データは食い違う)。

### 9.1 S2a スパイクの合格条件 (codex 案 + 私の追加)

代表的な K / L / M 端で、以下を**測って記録する**。⚠ **通ることを目的にしない** —
通らない項目が出たら、それが契約に書く制限になる。

| | 測ること | なぜ |
|---|---|---|
| G1 | β → 全角度で既存 `angular_integral` の値へ closure | 新経路が旧経路の一般化であることの検査 |
| G2 | β について単調増加 | §2.2 のゲートの最小形 |
| G3 | `n_x` を倍増しても動かない (β ごとに) | **小 β では求積区間が狭くなる**ので、既定 `n_x` が足りる保証は無い |
| G4 | 横断カーネルあり/なしの両方で G1–G3 | `coulomb_kernel` は K=0 なら点ごとにそのまま使えるはずだが未確認 |
| G5 | 複数 β をまとめたときの実時間 | **倍率は実測するまで言わない** (§2.0) |
| G6 | 小 β での Q² の桁落ち | 現行式 `k_i²+k_f²−2k_i k_f cosθ` は小角・高 E₀ で桁落ちしうる。`Q²=(k_i−k_f)²+4k_i k_f t` が安定だが**式を変えるとビット同一ではなくなる** |

⚠ **既存の K=0 分岐を一般化しない**。部分角用の別関数を足し、全角度は既存へ dispatch する。
現コードは総和順序までビット同一性に依存している。スパイク後に
`tools/bitident_snapshot.jl` の v3 5ch / v4 7ch を**両方**走らせて差分ゼロを確認する。

⚠ **有限 α への道を塞がない** (§8-4)。θ 分解された被積分関数を返せるようにしておけば、
非干渉な角度平均は後から積める。
