## 0. 何を突き合わせているのか

| | 既定 (契約が約束する側) | オラクル |
|---|---|---|
| **窓** (ε 積分) | √ε 上の単一 Gauss–Legendre 16 点 | √ε 上の**複合** GL 4 パネル × 12 点 |
| **角度** (θ 積分) | **log-x** 上の GL (n_x = PROD = 64) | **t = sin²(θ/2)** 上の複合 GL |

規模 = **525 チャネル × 全 E₀ = 14,796 行** × 窓 16 種 × β 8 本。
⚠ `Δ₂ > ε_max = T₀ − E_th` の窓は**契約の規則どおり拒否**して `out_of_domain` に数える
(= 認証行列そのものが入力検証の負のテストになる)。

## 1. ★ オラクルは本当に独立か — 窓側だけ変数が同じだった

⚠⚠ 角度のオラクルは **log-x → t** と変数を変えているが、**窓のオラクルは √ε のままで、
単一 GL → 複合 GL と刻み方だけを変えている**。このリポには
「自己収束テストが誤差を 26 倍過小評価した」前例があり ([[self-convergence-underestimates]])、
**同じ変数・同じ族の一致を収束の証拠にしない**という規律がある。

⇒ **第 3 の方法**を当てて測った (`tools/window_oracle_probe.jl`)。

**第 3 の方法 = tanh-sinh (二重指数型) を ε 上で直接** — √ε 置換を挟まない。
節点は `u_k = tanh((π/2)sinh(kh))` で端点へ二重指数的に寄り、閾値端の `√ε`
立ち上がり (代数的特異性) を変換無しで吸収する。GL 族とは節点も重みも生成則も無関係。

### 1.1 結果 — ⚠ **床の上でだけ判定する**

標本 = 7 チャネル (Z=6 K の閾値直上と高過電圧 / Fe K ×2 / Ag L3 / Au M5 / Au L3) ×
窓 5 種 × β 4 本 = **140 組**。

| 集計の範囲 | 比 (第 3 の方法が見る誤差 / 複合 GL が見る誤差) |
|---|---|
| **全 140 組** | 最大 **91.07** |
| **床 1e-07 の上にある 25 組** | 中央値 **1.10** / 最大 **2.10** |

⚠⚠ **全体の 91 倍は雑音である**。この engine は両経路が互いに **1e-08 で頭打ち**になることが
分かっており (原因未特定、`docs/next_chat_2026-08-19.md` §3)、1e-08 どうしの比は比ではない
([[signal-below-tolerance]])。**信号が床の上にある対だけで判定する。**

⇒ **複合 GL の窓オラクルは正直**である。第 3 の方法で測っても**係数 2.1 以内**。
26 倍の過小評価は起きていない。

⚠ ただし **これは 7 チャネルの標本での話**であって、全 14,796 行について
「オラクルが係数 2.1 以内」を示したわけではない。契約に書くときは標本を明記すること。

### 1.2 副産物 — 認証値との一致

同じ probe が出す `|既定 − 複合|` は、認証ハーネスの `worst_window` と一致する。
例: Z=6 K @30 keV、窓 [0,1000] eV、β=200 mrad で **9.48e-07** (認証の
`worst_window` = 9.479274360948259e-07 と同値)。⇒ probe と本体は同じものを測っている。

## 3. ホストのビット化けをどう測るか

`docs/host_stability_2026-08-19.md` の仮説 (このホストは散発的にビット化けする) が
正しければ、**認証結果そのものが汚染されうる**。

⚠ codex の指摘 (2026-08-18): 「各行で 16 窓 × 8 β の**最大値**を取るから単発の化けは
効きにくい」は**安全性の根拠にならない** — 化けは真の最大点そのもの・共通の SCF 状態・
全体に掛かる係数・添字・比較・被検査値とオラクルの両方、のどれでも壊せる。

⇒ **同じ入力をもう一度計算して突き合わせる**のが唯一の直接測定である。

### 3.1 何が測れるか (標本の大きさで決まる)

不一致 0 のとき、汚染率の片側 95 % 上限は約 **3/N** (N = 対の数):

| 対の数 | 上限 |
|---:|---:|
| 50 | 5.8 % |
| 500 | 0.60 % |
| 1500 | 0.20 % |

### 3.2 SCF の停止点差と、ビット化けを分ける

⚠ 不一致が出ても、原因は (a) ホストのビット化け か (b) 既知の
「SCF がプロセス間で散発的に別反復で止まる」現象か、そのままでは区別が付かない。

⇒ 行ごとに**始状態の指紋 `state_sha`** (束縛軌道 `u_b` と動径格子 `r_b` のハッシュ) を持たせた。

| `state_sha` | 認証値 | 読み |
|---|---|---|
| 一致 | 一致 | 正常 |
| **一致** | **不一致** | ⚠⚠ **始状態は同じなのに答えが違う** = SCF では説明できない |
| 不一致 | 不一致 | SCF の停止点が違う (既知の現象) |
